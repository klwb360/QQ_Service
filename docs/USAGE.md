# 使用指南

[返回首页](../README.md) · [功能实现与架构](ARCHITECTURE.md) · [开发指南](DEVELOPMENT.md)

## 1. 打开 Windows 应用

从 [最新 Release](https://github.com/klwb360/QQ_Service/releases/latest) 下载 `QQ_Service-0.2.1-Windows-x64.exe`，放在普通文件夹，例如 `D:\Apps\QQ_Service`，双击打开。适用于 Windows 10/11 x64。

EXE 自带 Node.js 和 npm，无需另装 Node、运行脚本或打开浏览器。便携 EXE 会自动展开运行环境，首次打开可能较慢。当前 EXE 未使用代码签名证书，Windows 可能显示发布者未知或 SmartScreen 提示。

关闭窗口会把应用收进托盘，继续采集消息和执行定时任务。右键托盘图标或「应用」菜单选择 **完全退出** 才会停止后台。若无法创建托盘，关闭窗口会完全退出。重复双击 EXE 会唤起已有窗口。

已启动的 NapCat Docker 容器在应用退出后会继续运行；需要停止时先在面板操作。电脑休眠、关机或应用完全退出时不采集新消息，也不补跑错过的定时汇总。

## 2. 安装所需模块

接入 QQ 需要先安装并启动 [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/)，使用 Linux 容器后端。首次启用 WSL 2 可能需要管理员操作和重启；仪表盘检查环境状态，不能代替 BIOS 设置。

在「总览」点击 **一键安装所选模块**，到「模块管理」查看进度与错误。

| 模块 | 用途 | 当前安装方式 |
| --- | --- | --- |
| NapCat | QQ 登录、收发消息和收藏接口 | 官方 Docker 镜像 `mlikiowa/napcat-docker:v4.18.37` |
| Codex CLI | 本人 ChatGPT 订阅授权与推理 | 官方 npm 包 `@openai/codex@0.149.1` |
| DeepSeek / 通知汇总 / 收藏 | 模型配置及相应工作流 | 应用内置功能，启用后还需完成配置和相关账号连接 |

NapCat 首次拉取后记录镜像 SHA-256 摘要，以后按摘要启动。Codex 安装在本项目数据目录，不修改全局 npm 安装。首版只管理本机 Docker daemon，不跟随远程 Docker context。

外部模块安装需要访问 npm、Docker Hub 与相关服务。网络失败会显示实际错误，不会换到未知镜像源或把失败记为成功。安装、服务运行、账号登录和模型连通是四种不同状态。

## 3. 登录 QQ 与模型

在「账号与模型」点击 **打开 QQ 登录页面**，按提示进入 NapCat WebUI，再用手机扫码登录机器人小号。填写 **本人 QQ 号** 和 **机器人 QQ 号**，两个账号应不同。小号需要加入希望处理的群。

DeepSeek 使用 API：填写 API Key，选择模型并启用，可在面板测试连通。密钥只交给后台调用 DeepSeek 官方接口。

使用 GPT 订阅时，安装 Codex CLI，点击 **启动官方设备码授权**。在授权任务输出中的 OpenAI 官方页面登录自己的 ChatGPT 账号并输入设备码，不需要复制账号 token。官方认证说明见 [Codex Auth](https://developers.openai.com/codex/auth/)。

订阅通道使用账号当前可用的 Codex 模型和额度，不是把 ChatGPT 网页会话直接搬到 QQ；网页历史、记忆和自定义 GPTs 不会自动带入。个人订阅用于本人请求，不能用于满足其他用户的请求，见 [Sign in with ChatGPT 条款](https://openai.com/policies/sign-in-with-chatgpt-terms/)。额度不足会显示失败，不会自动切换到付费 API。

## 4. 选定群并应用配置

在「场景与权限」添加群号，每个群选择一种用途：

| 用途 | 接收后的处理 | 允许发送到哪里 |
| --- | --- | --- |
| 社交群 | DeepSeek 聊天；可选 @、命令前缀或概率插话，配置冷却时间 | 当前选定社交群 |
| 工作群 | 仅记录消息，作为通知汇总资料 | 本人私聊；源工作群禁止发送 |
| 未选定群 | 不采集、不触发模型 | 禁止发送 |

设置助手风格、上下文数量、汇总模型与保留天数，然后点击 **保存并应用**。保存草稿不会改变正在运行的参数；应用后才切换。界面提供上一份普通配置回滚和无凭据导出。

配置变更会取消旧模型任务，发送前再次检查最新权限。回滚不能撤回已经发出的 QQ 消息，也不会回退已经更改的凭据。

## 5. 本人私聊与通知汇总

本人私聊机器人可以使用：

```text
/gpt 帮我解释这段通知：……
/ds 帮我整理这段文字：……
/summary 选定工作群号
/favorites
```

| 输入 | 行为 |
| --- | --- |
| 普通文字或 `/ds 问题` | 使用 DeepSeek |
| `/gpt 问题` | 使用本人已登录的 Codex 订阅 |
| `/summary 群号` | 汇总已选定且已有缓存的工作群 |
| `/favorites` | 整理当前账号已同步的收藏列表摘要 |

社交群始终使用 DeepSeek，群消息中的 `/gpt` 不会触发订阅。工作群消息只作为资料，不逐条触发 GPT。

通知汇总可以在面板立即运行，也可以每日定时。定时任务必须启用汇总、定时开关并勾选本人授权，按 **运行电脑的本地时间** 执行，每群每天去重。结果包含通知解释、行动项、原文写出的期限和消息引用；在「任务与记录」查看原始消息 ID、时间与文字依据。

「将汇总发送到本人 QQ 私聊」关闭时，面板运行的汇总只保存在本地。QQ 私聊命令明确要求回复本人，结果仍返回本人私聊。QQ 发送超时或部分分片已发送时会记录送达未确定或部分发送，不自动无限重发。

## 6. QQ「我的收藏」

先启用 QQ 接入和收藏模块，在面板点击 **读取已登录账号收藏**，再整理已缓存的列表摘要。收藏整理使用「通知汇总」里的模型和私聊发送设置，可以独立于工作群汇总开关使用；当前不支持定时收藏整理。

收藏来源是 **NapCat 当前登录的 QQ 账号**。小号不能自动读取主号收藏。第一版读取列表与接口摘要，不保证完整分页，也不获取收藏全文、图片、文件附件或网页正文。模型只解释已有摘要，重要通知仍需核对原文。界面保留收藏 ID、原摘要与时间；切换账号后需要重新同步。

## 7. 数据与备份

Windows 默认数据目录：

```text
%LOCALAPPDATA%\QQBridgeDashboard
```

目录名称保留旧版兼容，包含配置、SQLite 历史、NapCat 持久目录和独立 `codex-home`。数据不在 EXE 旁边或便携程序临时展开目录；移动或替换 EXE 后继续使用原数据。菜单可打开资料目录。完整备份时先停止 NapCat、完全退出应用，再复制这个目录。

DeepSeek/OneBot 凭据用 AES-GCM 保存，密钥位于同一数据目录，用于避免明文写入配置和导出；能够访问该目录的本机用户仍可访问资料。Codex 登录凭据由官方 CLI 管理，仪表盘不读取其 `auth.json`。配置导出不包含密钥、收藏或聊天历史。

选定群的原始消息与汇总依据保存在本地，按设置的保留天数清理。后台只监听 `127.0.0.1`，用于单个本机用户，请不要直接暴露到公网。

## 常见问题与当前边界

| 情况 | 原因与处理 |
| --- | --- |
| 模块已安装，但 QQ 未连接 | 还需启动 Docker/NapCat、扫码登录和应用 QQ 配置；查看四种独立状态 |
| 工作群汇总提示没有缓存 | 只处理机器人连接后实际收到的选定群消息，不回填全部历史 |
| 收藏返回不支持的结构 | 上游版本或接口返回不兼容；页面报告错误，不生成替代数据 |
| Codex 已登录但某模型失败 | 登录状态不代表拥有任意模型权限；检查实际可用模型、额度及任务错误 |
| 关闭应用后没有定时汇总 | 定时器在应用后台运行；保持托盘运行，休眠和退出时不补跑 |
| QQ 更新后掉线或接入失败 | NapCat 属于个人账号接入，受 QQ 更新和账号风控影响，见 [官方说明](https://napneko.github.io/other/security) |

Codex 用专用工作目录、只读沙箱和受限工具配置处理文字；检测到工具执行事件会拒绝结果。这不等于独立隔离所有本机读取能力，具体实现见 [架构说明](ARCHITECTURE.md)。
