# 使用指南

[返回首页](../README.md) · [功能实现与架构](ARCHITECTURE.md) · [Windows 原生 NapCat](NATIVE_NAPCAT_WINDOWS.md)

本指南对应 v0.4.1。首次使用按一个账号的六步引导操作：**账号与来源 → 模型准备 → QQ 连接 → 账号任务 → 范围与授权 → 验证效果**。多个账号可以同时运行；切换界面不会改变正在执行任务的所属账号。

## 1. 打开应用，创建账号

从 [Release](https://github.com/klwb360/QQ_Service/releases/latest) 下载 `QQ_Service-0.4.1-Windows-x64.exe`，放在普通文件夹，例如 `D:\Apps\QQ_Service`，双击打开。适用于 Windows 10/11 x64，自带 Node.js 和 npm。便携 EXE 首次展开可能较慢；当前未签名，Windows 可能显示发布者未知或 SmartScreen 提示。

窗口使用应用内标题栏，可最小化、最大化或关闭；原生菜单栏已移除。可在「设置」选择关闭按钮的行为：**默认最小化到托盘**继续运行，也可改为完全退出；这是所有账号共用的应用设置。托盘始终提供完全退出入口；无法创建托盘时，关闭会退出。重复双击会唤起已有窗口。后台只在本机运行；休眠、关机或完全退出时不采集新消息，也不补跑错过的定时汇总。

总览保留原有信息。首次进入「账号控制」只显示 **创建账号配置**，没有一整页需要提前理解的参数。创建后，每个账号显示为可以展开的设置项，内部按步骤完成配置；下次打开可继续处理尚未完成的步骤。微信和 Telegram 目前只有扩展规划，尚不能接入。

填写希望接入的 QQ 号，再选择需要的模型方式：API Key、ChatGPT 订阅，或同时选择。QQ 号指**实际准备登录、交给此应用处理消息的账号**，不要求使用“小号”，也不要求同时填写另一个“本人 QQ”。新配置默认只读，没有选定群，也不会自动运行模型或发送消息。

## 2. 配置模型凭据

同一个账号可以启用多个模型，之后为不同功能分别选择使用哪一个。启用多个 API 不表示同一条消息自动同时请求全部模型。

| 方式 | 需要准备 | 使用范围 |
| --- | --- | --- |
| DeepSeek | 自己的 API Key、模型名称 | 获准的群聊、本人任务、通知与收藏整理 |
| OpenAI 兼容 API | 服务名称、兼容接口地址、模型名称、该服务的 API Key | 与所选功能及 QQ 权限一致，需服务支持兼容接口 |
| ChatGPT 订阅 | 安装官方 Codex CLI，完成本人官方登录 | 本人明确发起或授权的个人任务，不供群友自动触发 |

API 下拉菜单提供 DeepSeek、OpenAI、阿里云百炼、智谱、Kimi、硅基流动，以及自定义兼容服务。预设只帮助填入地址和参数，不代表免 Key、免计费或所有模型都已实测；请按自己账户的服务区域与实际模型权限核对。

DeepSeek 使用官方接口。其他 API 根据你填写的地址发送任务内容，请使用自己认可的服务商；各项 Key 单独保存。兼容接口需要支持 Chat Completions，并提供可用的模型名称。连接测试会真实请求模型，API 可能计费，Codex 会消耗订阅额度。

Codex 为每个 QQ 配置安装官方 `@openai/codex@0.149.1`，点击登录后按输出打开 OpenAI 官方页面、输入设备码。无需粘贴 token；各账号使用独立登录目录，一次授权不自动授权其他配置。见 [Codex Auth](https://developers.openai.com/codex/auth/)。

Codex 使用本人订阅当前可用的模型与额度。ChatGPT 网页历史、记忆和自定义 GPTs 不会带入；额度不足不会自动切换付费 API。群友不能触发个人订阅的自动群聊，见 [服务条款](https://openai.com/policies/sign-in-with-chatgpt-terms/)。

填好凭据或完成模型登录后，QQ 账号仍然只读。安装完成、模型已配置、模型测试成功是不同状态。

## 3. 实际登录并连接 QQ

**NapCat 是连接组件，负责实际 QQ 登录和消息接口；模型负责理解文字。**在应用里填入 QQ 号不会登录 QQ，给模型登录也不会建立 QQ 连接。

如果 NapCat 已经安装并登录，不需要重装；直接检查接口、连接与实际身份，再继续选择功能和群。尚未准备 NapCat 且不想安装 Docker 时，使用 [Windows 原生指南](NATIVE_NAPCAT_WINDOWS.md)：

1. 用官方 Windows OneKey 安装器安装 NapCat，在生成的目录启动 `napcat.bat`。
2. 按 NapCat 控制台/WebUI 提示完成 QQ 登录，确认登录的正是刚才填写的账号。
3. 在 NapCat WebUI 启用 **WebSocket 服务器（正向）**，记下本机端口和 OneBot Token。
4. 在当前账号的 QQ 连接步骤填入相同的 WebSocket 地址和 OneBot Token，保存并建立连接。
5. 查看应用显示的**实际登录 QQ**是否与目标一致；连接失败时按该步骤的诊断处理。

注意两种 Token：WebUI Token 用来打开 NapCat 管理页，OneBot Token 用来让 QQ_Service 连接消息接口，不能混填。只有 OneBot 正向 WebSocket 服务可供当前连接方式使用，反向 WebSocket 不是同一配置。

已经安装 Docker Desktop 的用户也可选择应用内 Docker 安装。其前提是 [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/) 已运行、使用 Linux 容器后端；WSL 2、BIOS 和重启需按 Docker 提示处理。应用内安装/启动/停止 NapCat 管理的是 Docker 容器，**尚不提供原生 Windows NapCat 一键安装**。只使用 Codex 不需要 Docker。

Docker 使用官方 `mlikiowa/napcat-docker:v4.18.37`，首次安装记录镜像摘要，此后按摘要启动。多账号需要各自的 NapCat 实例、实际 QQ 登录资料、端口和 Token；不能让两个账号配置指向同一 OneBot 接口。原生 NapCat 由本人启动和停止，QQ_Service 不管理其进程。Docker 容器也可能在应用退出后继续运行。

QQ 连接本身不要求私聊接收 QQ，也不要求提前开通发送权限。判断是否连通应看实际 OneBot 连接和登录身份，而不是只看“模块已安装”。

## 4. 选择这个账号要做什么

在账号引导的功能步骤中设置，或进入「场景与权限 → 账号功能参数」继续编辑：

| 功能 | 设置内容 |
| --- | --- |
| 聊天与回复 | 启用开关、聊天模型、风格、上下文；群触发与发送范围在下一步设置 |
| 通知汇总 | 独立选择模型、条数、保留天数和时间；默认只在面板保存，可选私聊发送 |
| QQ 收藏整理 | 读取条数和独立整理模型；读取原始列表不依赖模型，整理时需要可用模型 |

聊天可选择 DeepSeek、已启用的兼容 API，或个人 Codex。选择 Codex 作为默认聊天模型时仅处理本人私聊，不自动群聊。通知和收藏可以分别使用其他模型，不需要都选同一个。

**保存草稿**只保存待应用参数。普通 **保存并应用** 更新参数并让当前账号回到只读；检查目标范围后需重新显式授权。模型与任务参数配置完毕，不代表允许发消息。

未释放权限时，已应用且允许读取的群可以记录连接后收到的消息；自动聊天和定时模型任务不会启动。你在面板明确发起的本地汇总、收藏整理与模型测试仍可执行，并使用相应模型额度。

## 5. 选择群与消息权限，最后授权

在账号引导中进入权限步骤，或打开「场景与权限 → 选定群与消息权限」。先读取实际已加入群，再选择需要处理的群，也可手动填写群号。读取群列表不会自动选中全部群，也不会回填历史或授权发送。

| 群设置 | 实际行为 |
| --- | --- |
| 未选择，或关闭读取 | 不缓存、不交给模型，也不发送 |
| 允许读取、关闭发送 | 缓存连接后收到的文字，可用作通知来源；不在该群回复 |
| 允许读取和发送 | 聊天启用、API 模型可用、账号显式授权后，才按勾选的消息/事件触发及冷却规则回复 |

### 群触发条件可同时勾选

每个群可选择 **@接入账号、命令前缀、低频主动插话、戳一戳、修改群名、群成员加入、群成员退出、管理员变更、禁言/解禁、撤回消息、群名片变化、消息表情回应**，支持全选与清空。默认只选 @；同时勾选时，满足任一已选条件即可按当前权限处理。清空代表不自动回复，不影响已授权的读取或本地整理。

“低频主动插话”是在收到新群消息时按概率参与，不是无人发消息时主动刷屏；全部触发均受冷却时间限制。“全选”只改变触发偏好，不授予读取、发送或账号启动权限。戳一戳默认只响应针对接入账号的事件。

群事件依赖 NapCat 实际上报，并且只用于生成获准的文字回复；勾选“修改群名”不会让 AI 自动修改群名，勾选“禁言变化”也不会授予禁言能力。撤回事件不保证能取回原消息正文。上游不同版本可能存在事件支持差异。

“工作群/社交群”描述用途，不代替授权。工作群默认不发送，也可由你明确允许 API 模型回复。通知只汇总已选且可读工作群的缓存，默认保存在面板，不发送回源群。

### 可选：通过另一个 QQ 私聊操作

只在需要私聊指令、私聊接收回复或汇总时，才填写 **私聊指令与汇总接收 QQ**，并允许私聊回复。它是有权向当前受控账号发起指令、接收结果的另一个 QQ，**不是必须登录的第二个受控账号**。

如果只想读群、在面板看整理结果，保持私聊回复和私聊汇总关闭即可，接收 QQ 可以留空。填写与受控账号相同的 QQ 不影响纯群/本地用途；若启用了私聊回复或私聊汇总，需改填另一个 QQ，或关闭相应私聊选项。应用会把原因放在相关字段旁，避免把它误解为 QQ 登录失败。

最后检查范围并点击 **启动此账号**（权限页为“确认授权范围”，验证步骤为“检查并授权”）。后台核验当前保存版本和真实登录身份，并显式释放该账号已配置的功能及目标。只允许读、不允许发的群，也能在启动后自动本地汇总，仍然零发送。未勾选发送的目标不会因启动账号而自动获准。

**立即恢复只读**会取消旧任务并阻止后续发送，不影响其他账号。普通应用和回滚也恢复只读；已经发出的消息无法撤回。

## 6. 验证一次完整流程

第一次建议只用一个测试群，先验证读消息，再决定是否开回复。按当前账号的完成情况逐项检查，避免直接打开全部功能：

1. **确认登录身份**：保持 NapCat 和 QQ_Service 运行，连接状态正常，实际登录 QQ 与配置一致。若不一致，先改为正确 QQ 登录，不要继续授权。
2. **确认模型**：运行该功能选中模型的连接测试，查看真实测试结果；只安装成功或填好 Key 还不能证明模型可用。
3. **确认新消息进入**：选择测试群、允许读取并应用，然后由群内正常产生一条新文字。查看当前账号的记录；应用不会导入连接前的全部聊天记录。
4. **确认本地整理**：需要通知汇总时，把测试群设为工作群并启用汇总，从面板手动运行。结果应出现在当前账号的任务/记录中，不需要另一个 QQ，也不需要群发送权限。
5. **按需验证自动回复**：选择可用 API 聊天模型、开启聊天，明确允许测试群读取及发送，最后释放权限；在群内 @实际登录账号 或使用已设置前缀发送测试文字，查看结果。Codex 个人订阅不参加自动群聊。
6. **确认最终范围**：看账号是否仍有待应用修改、未完成连接/模型/任务/权限项；不需要的功能关闭即可。失败时先处理当前步骤的提示，再重试该步骤。

需要确认 QQ 发送通道时，可点击 **向所选群发送一条测试消息**：仅向已配置且已释放读取/发送权限的测试群发送固定诊断文字，不调用模型。关闭发送权限或选择 Codex 自动群聊时不能使用此项验证，不会为测试自动授权。

群列表可读、策略预览通过、固定测试文字送达，分别证明不同环节；它们都不能单独证明模型已生成回答。真正的端到端效果需要你在实际账号完成上述操作。

### 私聊命令

启用相应功能并授权私聊后，指定接收 QQ 可向受控账号发消息：

| 输入 | 行为 |
| --- | --- |
| 普通文字 | 使用该账号默认聊天模型 |
| `/ds 问题` | 使用已启用的 DeepSeek |
| `/gpt 问题` | 使用该账号已登录的本人 Codex 订阅 |
| `/summary 群号` | 使用通知模型整理已选且可读工作群缓存 |
| `/favorites` | 使用收藏模型整理已同步的列表摘要 |

命令还需对应功能启用；未释放账号或私聊权限时不调用模型、不自动回发。发送超时或分片未完全成功会记录送达状态，不自动无限重发。

### 定时通知与收藏范围

定时汇总按**运行电脑的本地时间**执行，需要汇总开关、定时开关、明确后台授权及账号权限释放；每账号、每群、每日分别去重。没有私聊发送许可时，结果只保存在面板。重要行动和期限应核对输出引用的原消息。

收藏只能读取实际登录账号的“我的收藏”，先读取再整理，使用独立模型；账号 A 不会获得账号 B 的收藏。当前只取列表摘要，不读取全文、图片、附件、网页正文或完整分页，也不提供定时收藏任务。

## 7. 数据、升级与备份

升级前从旧版托盘选择 **完全退出**，再打开新版 EXE，避免唤起旧实例。先备份资料；需要回退旧版时恢复升级前备份。

Windows 默认目录为 `%LOCALAPPDATA%\QQBridgeDashboard`，保留旧名称兼容。`accounts.json` 保存账号目录；新账号位于 `accounts/<稳定ID>/`，各有配置、凭据、SQLite、模块和 `codex-home`。替换 EXE 不改变资料位置。旧版单账号沿用原根目录和登录资料；schema 1 迁移备份为 `config.v1.backup.json`，既有权限不扩大。

完整备份前停止相关 NapCat 并完全退出应用，再复制整个数据目录。原生 NapCat 登录资料由上游另行管理，需要另外备份。脱敏导出只含当前账号配置，不包含凭据、收藏或历史，可从应用内导出入口操作。

API Key/OneBot 凭据以 AES-GCM 保存，密钥同目录，不能隔离能访问该目录的本机用户。Codex 认证由官方 CLI 管理，面板不读取 `auth.json`。后台只监听 `127.0.0.1`，面向本机单个系统用户，不要直接暴露到公网。

## 常见卡点

| 提示或现象 | 含义与处理 |
| --- | --- |
| 找不到可执行程序 docker | 你选择了 Docker 安装路径；不想安装 Docker 时，改按原生 NapCat 指南部署，再填 OneBot 参数 |
| 连接被拒绝 / ECONNREFUSED | 对应端口没有可用服务；启动 NapCat，确认正向 WS 端口，不能把 WebUI 的 HTTP 端口填成 WS |
| OneBot 鉴权失败 | 对照 NapCat 网络配置中的 OneBot Token，不能使用 WebUI 登录 Token |
| 实际登录 QQ 与配置不一致 | 当前地址连到了另一个账号实例；检查登录账号、端口和配置 QQ |
| 私聊接收 QQ 与受控 QQ 相同 | 只影响已启用的私聊回复/私聊发送；换另一个接收 QQ，或关闭私聊选项继续群/本地用途 |
| 模型配置完成但测试失败 | 检查当前服务商地址、Key、模型权限、余额/额度；不代表 QQ 连接失败 |
| 连上 QQ 但没有记录 | 先应用目标群读取权限，再等一条新消息；不回填历史 |
| 模型测试通过却不回复 | 检查当前聊天模型、功能开关、目标群读取/发送、触发条件及最终权限释放 |
| 改完参数后停止自动处理 | 普通应用和回滚恢复只读；确认目标范围后再次释放 |
| 定时汇总未运行 | 检查本地时间、后台授权和权限释放，保持应用运行；休眠或退出时不补跑 |
| 收藏接口不支持 | 上游版本或返回结构不兼容；应用报告失败，不生成替代数据 |
| 多账号端口冲突 | 为各 NapCat 实例分配独立端口与登录资料，并在两端同步修改 |

运行范围与真实账号验收状态见 [验证记录](VALIDATION.md)。NapCat 的 [许可证](https://github.com/NapNeko/NapCatQQ/blob/main/LICENSE) 对商业用途与分发有限制，详见 [第三方声明](../THIRD_PARTY_NOTICES.md)。
