# 使用指南

[返回首页](../README.md) · [功能实现与架构](ARCHITECTURE.md) · [Windows 原生 NapCat](NATIVE_NAPCAT_WINDOWS.md)

本指南对应 v0.3.0。操作顺序是：**创建账号 → QQ 登录与模型配置 → 账号功能参数 → 群与消息权限 → 显式释放**。多个 QQ 账号可以同时运行；切换界面正在查看的账号，不会改变已经开始执行的任务目标。

## 1. 打开 Windows 应用

从 [Release](https://github.com/klwb360/QQ_Service/releases/latest) 下载对应版本的 `QQ_Service-0.3.0-Windows-x64.exe`，放在普通文件夹，例如 `D:\Apps\QQ_Service`，双击打开。适用于 Windows 10/11 x64，自带 Node.js 和 npm。便携 EXE 首次展开运行环境可能较慢；当前未签名，Windows 可能显示发布者未知或 SmartScreen 提示。

关闭窗口会收进托盘，继续运行各账号后台。「应用」菜单或托盘选择 **完全退出** 才会全部停止；无法创建托盘时，关闭窗口会退出。重复双击会唤起已有窗口。休眠、关机或完全退出时不采集新消息，也不补跑错过的定时汇总。

NapCat Docker 容器可在应用退出后继续运行，需要停止时在对应账号模块页操作。原生 NapCat 由本人单独启动和停止，QQ_Service 不管理其进程。

## 2. 创建账号，理解 QQ 连接组件

在「账号控制」创建一个 QQ 配置，填写名称和希望接入的 QQ 号。这里的 QQ 号是**实际准备登录并交由应用处理的账号**，不要求区分主号、小号或机器人号。

NapCat 是 QQ 连接组件：它负责实际登录 QQ、接收消息，以及提供群列表、收藏和消息发送接口。DeepSeek/Codex 负责理解文字，不能代替 QQ 登录。**输入 QQ 号只保存目标身份，仍需使用该账号实际扫码登录；后台会核对登录身份是否一致。**

每个账号可以有不同模型、场景、群权限和连接地址。新建账号没有选定群，默认不发送任何消息，不自动启用聊天或定时任务。平台列表中的微信、Telegram 仅是规划项，目前不能创建可用接入。

## 3. 准备连接和模型

先选定账号，再安装或配置该账号所需的模块。

| 模块 | 用途 | 方式 |
| --- | --- | --- |
| NapCat | QQ 登录、群与收藏接口、获准的消息收发 | 官方原生 Windows 安装器，或应用内 Docker 安装 |
| Codex CLI | 本人 ChatGPT 订阅授权与文字推理 | 应用内安装官方 `@openai/codex@0.149.1` |
| DeepSeek / 汇总 / 收藏 | 模型接入和工作流 | 内置功能，通过参数启用 |

### QQ：原生或 Docker 二选一

- **无需 Docker**：按 [原生指南](NATIVE_NAPCAT_WINDOWS.md) 用官方安装器部署 NapCat；在所选账号的「高级连接设置」填写本机 OneBot WebSocket 地址、OneBot Token 和 WebUI 地址。原生进程由本人启动。
- **应用内安装**：先安装并启动 [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/)，使用 Linux 容器后端，再在所选账号安装 NapCat。该按钮管理 Docker 容器，尚不是原生 Windows 安装器。WSL 2、BIOS 设置和重启需要按 Docker 提示完成。

Docker 使用官方 `mlikiowa/napcat-docker:v4.18.37`，首次安装记录镜像摘要，此后按摘要启动。各账号的容器、持久目录和本机端口分开。原生多账号同样需要各自独立实例、登录资料与端口，不能让两个配置指向同一正在使用的 OneBot 接口。

按对应 NapCat 页面或控制台提示，用手机完成 QQ 登录，然后启用该账号连接、保存并应用，核对实际登录身份。只读连接不需要填写另一个“本人 QQ”。

### DeepSeek 与 Codex

DeepSeek：在该账号填写自己的 API Key、模型和参数，密钥仅由后台发送给 DeepSeek 官方接口。连接测试会真实调用 API，可能产生少量费用。

Codex：为该账号安装官方 CLI，点击 **登录 ChatGPT / Codex**，在任务输出的 OpenAI 官方页面输入设备码。无需粘贴 token；每个 QQ 配置使用独立 Codex 登录目录，一个账号授权不会自动授权其他配置。见 [Codex Auth](https://developers.openai.com/codex/auth/)。

Codex 使用本人订阅当前可用的模型与额度，用于本人任务。群友不能触发个人订阅的自动群聊，见 [服务条款](https://openai.com/policies/sign-in-with-chatgpt-terms/)。网页历史、记忆和自定义 GPTs 不会带入；额度不足会失败，不自动转为付费 API。

安装、服务运行、QQ 已登录、模型已授权和允许发送是独立状态。安装成功或授权成功后，账号仍保持只读。

## 4. 设置每个账号的功能参数

在「场景与权限」选择账号，进入 **账号功能参数**。原快速场景预设已移除，各项由本人选择：

| 功能 | 参数与行为 |
| --- | --- |
| 聊天与回复 | 默认本人聊天模型选 DeepSeek 或 Codex；选 Codex 时只处理本人私聊。群自动回复要求选择 DeepSeek，目标和触发条件在权限子菜单设置 |
| 通知汇总 | 独立选择 DeepSeek/Codex、最大消息数、保留天数、时间与后台授权；默认本地保存，可选私聊发送 |
| QQ 收藏整理 | 读取条数和独立整理模型；纯读取不需要启用模型，整理时需对应模型已配置 |

只有对应功能启用后才执行相应任务。自动聊天与定时整理还需最后释放账号权限；未释放时，仅按已选读取范围记录消息，面板明确发起的汇总、收藏整理与连接测试仍可本地执行并消耗相应模型额度。配置模型并不意味着所有已加入群都会被读取或自动交给模型。

普通 **保存草稿** 不改变正在运行的配置。**保存并应用** 更新参数并把该账号恢复只读；检查群和目标范围后，还需最后一步显式释放发送权限。

## 5. 最后设置群与消息权限

进入 **选定群与消息权限**，为当前账号配置目标。可在连接 QQ 后读取实际已加入群，再选择使用范围；也可填写群号。读取群列表不会自动选择群、读取其历史或授权发送。

| 群设置 | 行为 |
| --- | --- |
| 未选定，或关闭读取 | 不缓存该群消息，不提交给模型，也不发送 |
| 允许读取、未允许发送 | 缓存连接后实际收到的文字；可作为已启用汇总的来源，不在群里回复 |
| 允许读取和发送 | 还需启用聊天场景、DeepSeek 可用，并显式释放账号权限；按 @、前缀或概率与冷却条件回复 |

「工作群/社交群」用于组织工作流。**工作群默认只读，但本人可以明确勾选发送权限并释放，让 DeepSeek 回复；群用途不会代替实际授权。**通知汇总的来源仍是已选且可读的工作群，汇总结果默认保存在面板，不发回源群。

如需本人私聊指令或私聊接收整理结果，在同一子菜单填写 **指令与汇总接收 QQ** 并允许私聊发送。它是可选的操作者/接收对象，不是第二个必须登录的受控账号；需要与当前登录账号不同。只在本地查看结果时可以留空。

最后点击 **检查并释放此账号权限**。后台校验所选账号的保存版本，只开放已配置的功能和目标。它同时是自动场景的授权入口：允许读取但关闭发送的群也可在释放后执行定时本地汇总，仍然零发送。没有勾选发送的群不会因为释放账号就获得发送权限；错误提示和汇总也不能绕过检查。

**立即恢复只读** 会阻止后续发送并取消旧任务，不影响其他账号。普通参数应用和配置回滚也会回到只读；回滚不能撤回已经发出的消息或回退已更改的凭据。

## 6. 本人私聊、通知与收藏

完成聊天功能和私聊权限设置后，指定操作者可私聊当前受控账号：

```text
/gpt 帮我解释这段通知：……
/ds 帮我整理这段文字：……
/summary 已选定工作群号
/favorites
```

| 输入 | 行为 |
| --- | --- |
| 普通文字 | 使用该账号的默认聊天通道 |
| `/ds 问题` | 使用 DeepSeek |
| `/gpt 问题` | 使用该账号已登录的本人 Codex 订阅 |
| `/summary 群号` | 使用通知模型汇总该账号选定且可读的工作群缓存 |
| `/favorites` | 使用收藏模型整理该账号已经同步的列表摘要 |

私聊命令还需对应功能启用；未释放账号或私聊权限时不调用模型、不自动回发。群消息不会触发个人 Codex 订阅。

通知可手动运行或每日定时。定时任务按 **运行电脑的本地时间** 执行，需开启汇总、定时、明确后台授权并释放账号权限；每账号、每群、每日分别去重。未释放时不会自动启动模型，仍可手动本地汇总。输出保留消息 ID、时间与原文依据，重要行动和期限应核对来源。没有私聊发送许可时，整理结果只保存在「任务与记录」。

收藏先读取再整理，使用自己的 `favorites.provider`，不再复用通知的模型或发送设置。面板整理默认仅本地保存；私聊 `/favorites` 在获准时回复指定操作者，当前不支持定时收藏任务。只能读取实际登录账号的「我的收藏」，账号 A 不会自动获得账号 B 的收藏。接口暂为列表摘要，不获取收藏全文、图片、文件附件、网页正文或完整分页。

发送超时或分片未全部成功时，记录实际送达状态，不自动无限重发。切换界面账号不会把执行中的任务、结果或登录流程转交给另一个账号。

## 7. 数据与升级备份

升级前先从旧版托盘选择「完全退出」，再启动新版 EXE，避免旧实例被唤起。建议先备份整个资料目录；如果需要回退旧版，应恢复升级前备份，避免旧程序读取 schema 2 配置。

Windows 默认数据目录：

```text
%LOCALAPPDATA%\QQBridgeDashboard
```

目录名称保留兼容。`accounts.json` 保存账号目录；新账号位于 `accounts/<稳定ID>/`，各自包含 `config.json`、`vault.json`/`vault.key`、`history.sqlite`、模块资料和 `codex-home`，数据不会放到 EXE 的临时展开目录。移动或替换 EXE 不改变资料位置。

旧版单账号升级为兼容账号，继续沿用原根目录和登录资料。配置草稿、应用版本及回滚版本升级到 schema 2，原配置备份为 `config.v1.backup.json`；旧权限精确映射，不额外授权。新建账号仍从只读开始。

完整备份前，停止相关 NapCat、完全退出应用，再复制整个默认数据目录。原生 NapCat 的 QQ 登录资料由上游单独管理，也要按上游说明另行备份。

DeepSeek/OneBot 凭据以 AES-GCM 保存，密钥在同一账号数据目录，用于避免配置和导出包含明文，不能隔离拥有该目录访问权的本机用户。Codex 凭据由官方 CLI 管理，面板不读取 `auth.json`。脱敏导出仅含所选账号配置，不包含凭据、收藏或历史。

资料按各账号自己的保留设置清理。后台仅监听 `127.0.0.1`，面向本机单个操作系统用户；不要直接暴露到公网。

## 常见问题

| 情况 | 处理 |
| --- | --- |
| 安装 NapCat 提示找不到 docker | 安装按钮走 Docker；先准备 Docker Desktop，或按 [原生指南](NATIVE_NAPCAT_WINDOWS.md) 手动接入 |
| 填了 QQ 号却没有登录 | QQ 号是期望身份；仍需 NapCat 扫码登录，再连接并核对实际身份 |
| 模型登录成功但没有回复 | 检查对应账号功能是否启用、群读取/发送是否勾选、是否已显式释放；默认聊天选 Codex 时不自动群聊 |
| 改完参数后停止回复 | 普通应用和回滚回到只读；确认范围后重新释放 |
| 只想读取通知，不想发任何消息 | 仅允许目标群读取，保持发送和私聊权限关闭；汇总保存在面板 |
| 群列表无法读取 | 先完成所选账号的 QQ 连接与身份校验；检查 OneBot 接口是否支持 |
| 群汇总没有缓存 | 仅收集连接后实际收到且允许读取的消息，不回填全部历史 |
| 收藏接口结构不支持 | 上游版本或返回不兼容，程序报告错误，不生成替代数据 |
| Codex 授权后模型仍失败 | 检查该账号实际模型权限、订阅额度和任务错误；授权不是任意模型可用保证 |
| 多账号端口冲突 | 使用独立 NapCat 实例、资料和端口；高级连接不能复用其他账号正在使用的接口 |
| 退出后没有定时汇总 | 保持应用托盘运行；休眠和退出时不补跑 |
| 设置了定时但一直未运行 | 除任务与后台授权外，还需在最后子菜单释放账号权限；可关闭所有发送许可，仅自动本地整理 |

Codex 通过专用工作目录、只读沙箱和受限工具配置处理文字；这与 QQ 发送权限是两层不同限制，见 [架构说明](ARCHITECTURE.md)。NapCat 的 [许可证](https://github.com/NapNeko/NapCatQQ/blob/main/LICENSE) 对商业用途与分发有限制，详见 [第三方声明](../THIRD_PARTY_NOTICES.md)。实际自动检查和真实账号验收状态见 [验证记录](VALIDATION.md)。
