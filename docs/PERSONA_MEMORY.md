# 人格、记忆和当前会话

v0.8.0 将稳定人格、确认式群友记忆、自身经历和临时会话分开。每个账号使用原来的稳定配置 ID，数据再按实际 QQ 和群号隔离；更换连接端不创建新的记忆库。

## 设置人格

在账号控制中展开账号，在任务配置内打开人格设置。填写角色正文、名字、外号和兴趣；同一个 QQ 的基础人格统一，各群可以继续配置自己的说话风格和兴趣。

角色正文支持最多4000字符的 Markdown 文本，可导入或导出 `.md`。预览展示当前草稿实际装配的人格，不调用模型、不保存参数。历史回退只将旧人格放回编辑草稿，仍需保存和应用；应用沿用只读和重新释放发送权限的流程。

普通聊天、自由聊天和工具助手共用人格装配。通知整理继续优先保证原文、行动项和期限准确，不套用娱乐性表达去改写事实。角色卡文本和群聊内容都不能替代后端权限判断。

## 三类记忆

| 类型 | 如何产生 | 如何使用 |
| --- | --- | --- |
| 群友事实与偏好 | AI 提出带原话来源的候选，或由所有者手动录入 | 所有者确认后才参与检索，不自动推断成员性格或关系 |
| 经历札记 | 在已经开启自由聊天、允许读取的群中，随已有聊天模型响应提出自身经历、表达习惯和待续话题 | 来源通过数据库核验后自动采纳；不能改基础人格、成员事实或权限 |
| 当前会话 | 根据真实已保存互动维护话题、参与者、最近互动和待续事项 | 临时使用，默认两小时过期，不转为已确认事实 |

在「设置 → 群友记忆」中切换「群友记忆」「经历札记」「当前会话」查看。先选择所属 QQ 和群；这些目录不会合并不同身份的数据。

自动经历每轮最多两条、每条最多300字，只有成功互动后才积累，不从无人请求的浏览结果、事件通知或失败发送中生成完成记录。复用现有模型轮，不默认增加后台整理请求；每次仅检索最多8条相关经历。已发布的 v0.8.0 每群活跃记录最多40条，开发分支扩大到440条，超出后归档。人工编辑允许更长正文，自动生成和模型取回预算保持不变。

可以暂停自动积累、编辑、查看版本、回退或归档。**删除经历会清除正文、来源和全部版本，无法回退**；仅保留不可逆去重指纹，防止相同内容立即被再次自动记入。归档适合暂时不用但希望保留的内容。

## 清空当前会话

清空会话会取消尚未发送的旧回答，清掉临时话题、参与者与待续状态，并停止向模型携带清空前的短对话。历史原文、已确认成员记忆和经历札记仍保留；需要忘记长期内容时，应分别在对应页删除。

正在执行的外部写入不会因清空而自动重试；若操作结果不明，请先到对应应用核对。

## 保存容量与目录（开发分支）

开发分支将有上限的保存容量增加1000%，即原来的11倍。以下是存储／人工编辑上限，不是要求模型每次生成或读取的数量：

| 项目 | 保存上限 |
| --- | --- |
| 对话原文 | 330天，单条最多132000字符 |
| 人工成员记忆 | 单条6600字符 |
| 经历札记 | 人工编辑单条3300字符，每群440条活跃记录 |
| 管理列表 | 最多11000条 |
| 人格历史读取 | 最多1100条；未新增版本总量限制 |

模型仍只在原有预算内查找相关记忆，对话取回范围仍为最近30天，当前会话仍默认两小时失效。自动候选的输出数量和长度、角色卡4000字符上限都保持不变。保存更久不等于把全部存档塞进每次模型请求。

在「设置 → 记忆保存位置」选择文件夹并保存，**完全退出应用后重启**才迁移；关闭到托盘不会生效。默认每账号的 `memory.sqlite` 位于原资料目录；自定义根目录使用 `profiles/<稳定账号ID>/memory.sqlite`，仍隔离账号、实际 QQ 与群。网页／Docker 中填写的是服务所在电脑或容器的路径。

目录切换只迁移记忆、经历、会话和人格版本，不搬模型密钥、账号配置、QQ 登录或任务账本。先校验再切换，保留旧源与备份；失败会继续使用原目录。缺少已初始化的记忆库时不会创建空库替代，也不会回读旧历史库“恢复”已删除的记忆，请重新连接原磁盘或恢复完整备份。

## 升级与备份

v0.8.0 将旧配置升级至 schema 3，原人设、名字、外号、群风格、模型密钥、历史与权限不会因迁移而新增授权。开发分支在原账号身份下将记忆拆到独立数据库，首次拆分保留 `history.pre-memory-split.backup.sqlite`，原历史库不删除。

备份前完全退出应用，复制整个主数据目录，包括 `vault.key`、`vault.json`、账号资料身份文件、SQLite 及目录指针；**使用自定义记忆目录时，还需同时复制该目录全部内容**。原历史库备份不能代替之后新增或删除过的记忆库。完整步骤见 [数据与备份](USAGE.md#7-数据升级与备份)。

开发分支提供固定SnowLuma 2.4.2-node／OneBot v11的外部实验适配，用户自行准备并运行实例；公开TS／WebUI构建及协议夹具已验证，Windows动态安全和真实QQ仍待验，外部适配可用不等于其原生组件已经审核安全。应用不下载、安装、启动或分发这些组件，见[审查记录](SNOWLUMA_SECURITY_REVIEW.md)和[构建证据](SNOWLUMA_BUILD.md)。

连接端切换或重连不改变稳定profile、实际QQ和群级记忆身份，不清空人格、成员事实或经历札记。消息动作则使用带连接端和每次连接代的规范引用：旧历史仍可读取、旧原始编号不自动升级为可操作证据，只有当前代中核实过的消息才能作为引用、回应、合并转发或撤回目标。切换后仍恢复只读并取消旧任务，需要重新确认群与发送范围。
