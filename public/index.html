  1. 安装并启动 NapCat
    原生方式无需 Docker。按官方说明安装并启动，保持它在后台运行。
    打开 NapCat 官方安装说明 ↗
  2. 扫码登录这个 QQ
    使用下方管理页面登录，确认扫码账号与“接入 QQ 号”一致。QQ 号输入框不能代替扫码。
  3. 在 NapCat 添加网络配置
    选择 WebSocket 服务器（正向） 并启用，地址填 127.0.0.1，端口与下方 WebSocket 地址一致（通常 3001）。将同一个 OneBot Token 填入两边，然后保存。

            
此路线需要已安装并运行 Docker Desktop，使用 Linux 容器。如果没有 Docker，请选择左侧原生路线。

第 5 步
选定群与消息权限
功能决定做什么，权限决定它可以读取和发送到哪里。
只有一个 QQ 也可以接入。读取群、群聊回复、本地汇总均不需要再填“本人 QQ”。只有让助手回复你的私人指令，或把汇总发给另一个 QQ 时，才设置私聊接收账号。

按账号逐步配置功能与权限

        

          
这里设置当前账号要使用的功能与模型。应用参数会恢复只读；仍需进入「选定群与消息权限」显式释放发送权限；只读状态也可以在本地整理通知与收藏。

          
聊天与回复
对话模型与风格属于当前账号，实际发送范围由消息权限控制。

          
通知汇总
梳理当前账号选定工作群的通知、行动项、期限与原文依据。
立即运行使用此账号的已应用配置，可能消耗所选模型额度；无发送权限时仅保存本地。

          
QQ「我的收藏」
只读取当前实际登录 QQ 的收藏。
当前支持收藏列表与接口提供的摘要；完整正文、图片、附件和跨页同步尚未验证。一个 QQ 无法读取另一个 QQ 的收藏。
使用此账号独立选择的收藏模型，仅处理已读取的列表摘要。

等待后台状态
正在读取已应用权限。
释放前会保存并校验下方的群与私聊范围；后台只向已授权目标发送。此按钮是完成配置后开启自动任务的最后一步。恢复只读立即阻止后续发送，其他账号不受影响。

          
选定群与消息权限
只存储明确允许读取的群消息。每个群单独设置读取和发送；群用途本身不会授予权限。
群名称 / 群号使用方式触发条件参数消息权限
新增群默认只读。群回复需同时启用聊天功能、勾选该群发送权限，并显式释放账号权限；工作群默认仅采集，确需回复时也必须逐项授权。

          
私聊指令与汇总接收（可选）

私聊发送权限
需在上方显式释放账号权限后生效；未配置接收 QQ 或未允许私聊发送时，结果仅保存在本地。本人可使用 /gpt、/ds、/summary 群号、/favorites。
